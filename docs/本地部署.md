# Q金本地部署

更新日期：2026-11-16。以下步骤面向 macOS 本机单用户 CE。网页源码是当前发布快照；`extras/desktop/` 是 2026-11-10 的桌面 2.1.1 历史源码，尚未用最新网页源码重新打包。新机器安装、本人授权和完整媒体链路尚未完成验收。

## 环境准备

安装 Python 3.11 或 3.12、uv、Node.js ≥24、pnpm 11.5.0，以及 FFmpeg/FFprobe。Python 版本范围以根 `pyproject.toml` 为准，前端包管理器以 `frontend/package.json` 的 `packageManager` 为准。不要用历史桌面 `python-dependencies.json` 替代根 `uv.lock`。

在仓库根目录安装 Python 依赖：

```bash
uv sync --group dev
```

在 `frontend/` 安装前端依赖：

```bash
pnpm install --frozen-lockfile
```

秘密只配置在目标机器的私人环境文件或钥匙串，不复制其他机器的 `.env`、状态目录、浏览器身份或数据库。

## 本机网关

豆包工作网关要求 macOS、Node.js ≥24，无外部 npm 依赖，固定监听 `127.0.0.1:8791`。完整平台配置、回调与权限步骤见 [网关说明](../extras/gateway/README.md)。不要在已有 8791 服务运行时重复启动，也不要只改监听端口。

将 `extras/gateway/` 保持在稳定位置。在该目录的本人终端执行：

```bash
npm run configure
npm run prepare-local
npm start
```

服务启动后，在同目录的另一个本人终端执行：

```bash
npm run authorize
npm run status
```

配置时隐藏输入 Secret，授权在本人浏览器完成。不要将 Key、令牌或一次性授权链接写入共享日志。

业务客户端优先读取 `QJIN_DOUBAO_GATEWAY_PROJECT`，未设置时回退到仓库 `extras/gateway/`。网关身份按安装目录计算指纹，环境变量必须指向实际网关安装目录，而不是项目根目录。若使用独立安装位置，在启动后端前设置其绝对路径：

```bash
export QJIN_DOUBAO_GATEWAY_PROJECT="/absolute/path/to/gateway"
```

移动网关目录会改变钥匙串与状态目录指纹，须在新位置由本人重新配置和授权；仅设置相同 URL 不能恢复旧身份。保持 OAuth、Bearer Key、Host/Origin、PKCE、DPoP 与加密保护，不搜索或复制其他身份。

## 启动网页

在根目录设置本机网关位置和私人数据目录。以下数据目录独立于发布源码：

```bash
export QJIN_DOUBAO_GATEWAY_PROJECT="$PWD/extras/gateway"
export NOVELVIDEO_DATA_ROOT="$HOME/Library/Application Support/QJin/source-data"
export NOVELVIDEO_STATE_DIR="$NOVELVIDEO_DATA_ROOT/state"
export NOVELVIDEO_OUTPUT_DIR="$NOVELVIDEO_DATA_ROOT/output"
export NOVELVIDEO_RUNTIME_DIR="$NOVELVIDEO_DATA_ROOT/runtime"
export NOVELVIDEO_API_HOST=127.0.0.1
export NOVELVIDEO_API_PORT=8780
export SUPERTALE_FE_HOST=127.0.0.1
export SUPERTALE_FE_PORT=5173
bash scripts/start-ce.sh
```

若网关安装在其他位置，用实际绝对路径替换上面的网关变量。启动器会准备 CE 环境、项目 Codex、依赖、API 和前端；首次运行可能下载依赖。它会创建或读取根 `.env`，该文件必须保持私有；不要把旧机器环境文件复制进发布仓库。

前端 `VITE_API_URL` 应为 `http://127.0.0.1:8780`，可写入私人 `frontend/.env.local`。改变 API 端口时同步修改前端目标。前端开发命令为 `pnpm dev`，CE 构建命令为 `pnpm build:ce`，测试为 `pnpm test`；在 `frontend/` 执行。

打开 `http://127.0.0.1:5173/`，检查 `http://127.0.0.1:8780/api/v1/config`，再检查设置中的豆包工作连接与本人授权状态。Ctrl+C 结束启动器创建的网页服务；网关由其自己的终端管理。不要停止其他已有实例。

未配置其他模型网关不代表所有能力不可用，也不能把本机豆包工作连接成功当作音频、Embedding、翻译或本机工具已开通。可选素材归档需要目标机器本人的 lark-cli 和授权。

## 桌面打包边界

历史 `build.cjs` 要求同级 `desktop/`、`dramaclaw/`、`doubao-work-api/`，与本仓库根源码加 `extras/` 的布局不同，不能直接在 extras 下执行旧打包脚本。重新打包应在仓库外建立干净 staging，只放经过审阅的源码，排除凭据、运行数据、生成媒体及依赖缓存。

最新后端的桌面兼容性、新旧图标一致性与新机器完整链路仍须验收。历史应用后端默认回环 18780，占用后顺延；数据、浏览器和日志位于用户 Application Support，不应写入签名包。历史签名为 ad-hoc，未提供 Apple 分发签名或公证。

扫描命令在仓库根目录执行，工具通过 PATH 提供；报告应放在仓库外：

```bash
gitleaks dir . --redact=100 --no-banner
gitleaks git --pre-commit --staged --redact=100 --no-banner
```

目录扫描不是 Git 历史扫描，也不是二进制 OCR、平台授权或功能验收。完整许可证见根 `LICENSE` 与 `LICENSES/`；附加组件来源见 [extras 说明](../extras/README.md)。
