# 导入与使用

版本1.1.0：修正原文冲突并转换为1个原生Skill＋6个Recipe。

1. 解压本包，在 Q 金「设置 → 画布 Skills → 导入 Skill」选择 `viral-video-oneclick.skill-bundle.json`。
2. 这是原生JSON，不需要「导入外部 Skill」的AI转换。若选外部导入，则只上传SKILL.md。
3. 打开项目，上传参考视频和商品图，选择「参考视频换商品」，填写目标商品名、模式和每段候选数。
4. 先提供或执行真实带时间戳转写；文本Recipe只能整理证据，不能替代ASR。将素材锚点连到对应阶段；生成节点必须拥有实际视频参考能力。
5. 视频完成后补充真实成片转写和抽帧证据，再运行核验节点。待核验或不合格不计为合格。

## 修正记录

- 获取不到原文时暂停，删除「按常见话术编写台词」的兜底。
- 没有可读取视频时暂停，删除「链接模式改模板、用文字替代视频却声称复刻」的兜底。
- 模板固定核心约束，明确允许填入区间、执行台词、商品名、时长和画幅。
- 原文30秒保留为可核实的源目标上限；当前画布默认15秒，避免预检提示的拆分／截短。15秒按75–90字以内分段，仍以时间和自然语速检查。
- 每段候选数与完整模式段数分开，不混用。
- 原文商品名与目标商品冲突必须单独授权；授权修改后保留替换记录，不称原文逐字复刻。
- 保留真实服务所需确认；不通过Skill声明绕过。
- 语音转写、抽帧核验、候选重试是需要工具或人工证据的步骤；不冒充新增自动执行器。
- 保留逐段原声交付；用户要求拼接时再用现有视频合成节点。

原生Bundle格式、Skill/Recipe引用、内容扫描、两个代表场景的画布拓扑、ZIP结构与Markdown导入读取通过。详见validation.json。
这些都是静态兼容性检查。未执行真实生成、转写、核验或付费调用；未安装到用户技能集合。当前通道的模型、参考视频、时长和音频能力须在使用前核实。
